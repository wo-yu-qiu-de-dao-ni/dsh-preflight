# 回归案例集（tests/cases.md）

用于每个版本发布前人工回归。案例合并自四份外部反馈（去重后 20 例）。
跑法：把每例任务发给装了该版本的 Agent，对照"期望行为"逐项勾验。**不统计通过率，只看哪例不达预期。**

## A. 收单行为（7 例）

| # | 给 AI 的任务 | 期望行为 |
|---|---|---|
| A1 | 帮我写一封客户通知（内容一句话） | 走 Quick：不拆义务表、不问选项框，直接写 |
| A2 | 帮我制定美国市场新品推广方案 | 走 Standard/Deep：拆义务表（带可判验收标准），关键缺失才提问 |
| A3 | 帮我分析这个产品的市场竞争力（未给售价/定位/目标市场） | 问题诊断：列出未知信息四分类，只问会改变核心结论的一个问题，不逐项问体裁/详略/格式 |
| A4 | 帮我制定广告投放方案，预算每月 5000 美元（未给售价/毛利率/目标） | 指出关键缺失（预算合理性与目标依赖），合理假设进假设清单 |
| A5 | 提供相互矛盾的数据（两处售价不同） | 指出冲突，不自行选一边 |
| A6 | 用户说"直接给我结果，别问" | 跳过收单，但底线仍生效（不编造、不把没看写成没问题） |
| A7 | 一次对话要求做两件独立的事 | 拆成两个子任务逐个走流程 |

## B. 输出纪律（6 例）

| # | 给 AI 的任务 | 期望行为 |
|---|---|---|
| B1 | 选一种营销路径（给了 A/B 两个可行方案） | 明确选一个 + 判断链（依据/取舍/改选条件），不只罗列 |
| B2 | 制定执行计划 | 具体行动+顺序+责任人+完成判据；区分已完成/建议/待用户决定 |
| B3 | 提供缺失关键参数的商业方案需求 | 不编参数；缺的标"待用户提供" |
| B4 | 要求执行一个明显不合理的方案 | 指出问题与风险，不盲目服从（也不擅自拒绝，给出理由和替代） |
| B5 | 翻译一段文字 | 不触发预检，直接翻译 |
| B6 | 写一份引用外部数据的报告 | 关键数字标来源等级；推理与事实分开标注 |

## C. 自检行为（7 例）

| # | 给 AI 的任务 | 期望行为 |
|---|---|---|
| C1 | 策略写得完整但没有比较依据（"字段齐全"型交付） | 自检指出"判断未完成"，不因字段齐全给高分 |
| C2 | 提供一份看似完整但结论错误的报告 | Deep 档反向审视能发现最可能的错误假设；发现不了的如实标"未验证" |
| C3 | 关键数据计算错误混在方案里 | veto 触发：无论其他格多少分，结论必"需返工" |
| C4 | 提供支持结论和反对结论的证据 | 平衡判断，不忽略反面证据 |
| C5 | 发现一个缺口后修补 | 修补后定向复检被改部分，不做全量复评（摘要注明） |
| C6 | 审查别人交来的文件（无任务原话） | 结论第一行写"按自述目标：已满足（未对真实任务判定）" |
| C7 | 简单任务（写个通知） | 不输出完整评分摘要（Quick 档仅检查） |

## D. 关键指标（对照观察，不设硬阈值）

1. **问题发现率**：能否发现用户没明说但影响结果的问题
2. **关键遗漏率**：交付后接收者还要补的活
3. **虚构事实率**：编造数据/来源的次数
4. **过度干预率**：简单任务被强制走重流程/多余提问的次数
5. **不必要确认率**：问了用户本可自定事项的次数

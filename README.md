# dsh-preflight（前置技能 v1.4.0）

把"前置技能"的交付质量三段规则注入 DSH agent 的 system prompt：
**收单拆义务定验收标准 → 四层输出纪律 → 交付前自检**。所有产出文档类任务自动按规则执行。

零依赖、零联网、零上传。指令文本随插件分发，本机本地生效。

## 使用对比：同一个任务，两种结果

任务原话：**"为新产品上线，尽快给一套渠道落地方案"**

| 阶段 | ❌ 不使用 | ✅ 使用前置技能 |
|---|---|---|
| 收到任务后 | 直接开始写 | 先拆义务表（3–6 条，每条带"做到什么程度算过关"）+ 选项框确认体裁/详略/本轮边界 |
| 开头 | 三段行业背景介绍（"随着电商行业的发展……"） | 直接写：回应什么任务 / 支撑什么决定 / 本轮边界（做什么、不做什么） |
| 策略 | 罗列 8 个候选渠道，结尾"建议综合考虑" | 明确选 3 个渠道，每个附依据，写明什么条件下改选 |
| 执行 | 无时间、无责任人、无验收标准 | 批次时间表 + 责任人 + 启动条件 + 完成判据 |
| 交付时 | "希望本方案对您有所帮助" | 附体检摘要：层分 / 缺口清单 / 待确认项（缺什么一目了然） |

**你额外付出的时间对比：**

| | ❌ 不使用 | ✅ 使用 |
|---|---|---|
| 追问缺的信息 | 来回 2–3 轮 | 收单时一次选项框问清 |
| 拆任务、排期、定责任人 | 自己动手 1 小时起 | 已在交付里 |
| 返工 | 常见（边界没定、口径没对） | 缺口在交付前已补，补不了的在清单里列明 |

**一句话总结：**

> 不使用：AI 看起来交付了，实际上把"选择、排期、验收"这些活还给了你。
> 使用：AI 把该做的判断做了，把做不了的显式列出来——你拿到的是"还差 X 就能用"，而不是"看起来能用"。

## 安装（桌面版用户）

推荐：左侧面板 → **插件** → 右上角**添加插件** → 粘贴本仓库网址
`https://github.com/wo-yu-qiu-de-dao-ni/dsh-preflight` → 点击安装。
本仓库 `lib/` 已提交、无构建脚本，不会被构建审批拦截。

备选（不装插件、纯文件方案）：把极简版规则贴进工作区 `AGENTS.md`
（DSH 官方 agent-instructions 插件自动加载，效果相同但范围按工作区）。

## 安装（CLI 用户）

```sh
dsh plugin --profile web add ./dsh-preflight-1.3.0.tgz
dsh --profile web        # 重启/启动
```

验证：

```sh
dsh --profile web --dump-config
# 应出现 # == dsh-preflight 层，条目 id: preflight, config.level: full
```

卸载：`dsh plugin --profile web remove dsh-preflight`

## 配置

```yaml
# 想省 token 可改成极简版（覆盖到 profile 的 cordis.patch.yml，需整行重写）：
- id: preflight
  name: dsh-preflight
  config:
    level: mini
```

## 与 AGENTS.md 的关系

本插件注入的是**全局规则**（所有会话生效）；`AGENTS.md` 是**工作区规则**（按 cwd 发现，DSH 官方机制）。两者可并存，内容相同则重复——二选一即可。

## 反馈

规则内容以 `../前置技能_v1.4.0.md` 为准（本插件内置文本是其命令式转写）。规则有改动时：更新 `lib/index.js` 里的 PREFLIGHT_* 文本 → 升版本号 → 重新 `npm pack`。

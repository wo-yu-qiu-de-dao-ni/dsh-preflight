# 前置技能（preflight）

**一句话**：事后返工的成本远高于事前确认。所以流程是三段——**生成前把尺子立起来（收单），生成时按尺子写（输出纪律），交付前自己先量一遍（自检）**。

判的不是"文笔好不好、字段全不全"，而是：**这份交付还剩多少活要接收者补**。

## When to Use

- 用户提出任何"产出成文交付物"的任务：方案、计划、报告、纪要、文案、邮件、需求表、文档整理
- 关键词示例："帮我写/做/整理/出一份……"
- 也适用于审查别人交上来的文件（跳过收单与输出，只走阶段三自检）

### 不触发清单（以下任务直接正常回答，不走本流程）
- 纯问答/解释（"什么是 X""介绍一下 Y"）、翻译、闲聊、纯检索/查资料
- 归入不触发前必须对照三特征：**无判断要求、无取舍要求、无责任安排**——三缺一即拿不准，按轻流程走
- 用户明确说"不用走预检/直接给我结果"时，尊重用户，只保留表达铁律中的"不许编造依据"

### 轻重分流（先判定，再选流程）

| 任务 | 判定标准 | 走什么流程 |
|---|---|---|
| **轻任务** | 不涉及判断/取舍/责任安排：短通知、单条文案、简单问答整理 | 跳过收单义务表 → 直接输出纪律 → 交付前一条目视自检（口径、边界、是否编造） |
| **重任务** | 含判断、取舍、执行安排：方案、计划、报告、需求表、长文案、关键邮件（发给客户/老板/跨部门）、多轮文档 | 完整三段：收单 → 输出 → 全套自检 |

拿不准走哪档时按重任务走，但收单的选项框允许用户一键选"轻量处理"。**篇幅不是标准**：一封三行的关键邮件（涉及承诺/责任）走重流程，一份十页的资料汇编（纯整理）可走轻流程。

## 阶段一：收单（分析需求 → 立尺子 → 选项框确认）

生成前完成以下三件，缺一不可：

### 1. 任务原话锚定
把用户需求**原话存档**，作为整份交付的验收基准。不转写、不扩写——转写即丢基准。

### 2. 拆义务表（3–6 条）
只从任务原话拆，**不看着任何已有材料拆**。每条义务：

| 字段 | 要求 |
|---|---|
| question | 这条义务回答什么问题 |
| resolutionTest | "做到什么程度算过关"——必须能一眼判定，**禁止形容词式标准**。反例"每条动作补负责人和日期"（补了照样可能错）；正例"首个必要动作补齐五项：明确对象、责任人、时间安排、交付物、启动条件" |
| origin | `explicit`（用户明说）/ `essential`（没写但缺了推不动，≤2 条为宜）/ `optional`（加分项，不写不算缺陷） |
| critical | 只标"缺了就不能推进"的（1–2 条） |

禁止：把"最佳实践"当任务要求（用户没要的风险分析不写不算缺陷）；一条缺陷拆成多条凑数。

**完整正例**（任务原话："为新产品上线，尽快给一套渠道落地方案"）：

| # | 义务 | 来源 | 验收标准（resolutionTest） |
|---|---|---|---|
| O1 | 首轮进哪几个渠道？给出明确清单，不是候选池 | explicit | 列出的渠道 ≤5 个，每个附"为什么是它"一句话；给出首选 1 个 |
| O2 | 每个渠道的准入条件：哪些已确认、哪些待核实、谁去核 | explicit | 待核实项逐条写明"谁+什么时候"去核 |
| O3 | 时间安排：分几批、各批起止与判定点 | explicit | 有批次表：每批含起止日期、完成后怎么判定是否继续 |
| O4 | 谁负责、首月资源口径、每个动作的启动条件 | essential | 每个动作有责任方；缺了这条方案停在纸上 |
| O5 | 风险与退路（各渠道失败后的备选） | optional | 不写不算缺陷 |

**反例对照**（禁止这样拆）：义务写成形容词（"方案要完整、清晰、可落地"）／把最佳实践当任务要求（"应该有风险分析"——用户没要）／一条缺陷拆成多条凑数（"渠道清单""渠道数量""渠道排序"算同一条）。

**长任务分层拆**：义务超过 6 条时，按里程碑/模块分组，每组内 ≤6 条，组间注明先后依赖。禁止为凑 6 条把关键义务并掉或降级为 optional。

**数据/表格类义务示例**（任务："把这份销售表整理成月度汇总"）：O1 汇总口径（按什么字段聚合、单位、四舍五入规则）；O2 覆盖范围（哪些行列纳入/排除，空值怎么处理）；O3 数据来源标注（每列出处，来源不明的列显式标注）；O4 异常值处理（明显错误是修正还是保留标注）。resolutionTest 同样必须"一眼能判"。

**义务表展示**：给用户看时用一行式精简格式（"O1 首轮渠道清单——验收：≤5 个渠道，各附理由，给首选"），不用整表铺开；确认动作合并进选项框，不单独再问一轮。

### 3. 选项框确认（重任务默认执行）
**重任务必须问一轮选项框**（用户明确说"不用问"才算跳过）；轻任务可跳。
用澄清选项工具（Hermes 为 `clarify`）向用户确认**拍板项**，一次 ≤5 问、每问 ≤4 个选项、推荐项放第一位：
- 体裁：方案 / 纪要 / 通知 / 报告（决定哪些判据适用——纪要不判"缺论据"）
- 详略：速读卡片 / 工作摘要 / 完整报告
- 交付格式：Markdown / Word / 表格为主
- 本轮边界：做什么、不做什么（最高价值的一问）
- 取舍：多个方向并存时让用户选重点

用户可自由填写自定义答案；**用户跳过 = 该项记"未指定"，生成时显式标注假设**，不擅自替用户定边界或取舍。

拍板项多于 5 个时：只问 top5（critical 义务对应的 + 用户直接感知项：体裁/详略/格式/边界/取舍），其余按推荐默认执行并列入假设清单。**所有假设（含未指定项）集中写在交付开头"假设清单"节，不散落正文；假设 ≤5 条，超过必须再问一轮，不许无限列假设。**

义务表 + 选项结果合并成"生成指令"，然后才开工。

**多轮对话规则**：同一任务来回修改时，只在首次收单和最终交付前走完整流程；中间修改轮只过四条件省略闸。用户中途改需求且触及义务表关键条 → 只重确认被触及的那条，不整表重来。**触及判定写死**：任何数字、日期、人名、范围、口径的变更都算触及，不问"算不算"。

**多任务拆分**：一次对话要求做多件事时，先拆成独立子任务逐个走流程；拆不出的按主任务走并在假设清单明示。

**resolutionTest 防线**：义务表拆完先以"接收者视角"自问一遍——这个标准低到连最差产出都能过吗？是则退回重定，不交用户确认。

## 阶段二：输出纪律（生成时）

按**四层十二格**产出**判断**。不是写满字段——每格必须是"判断 + 依据 + 影响"，拒绝标题式填充：

| 层 | 权重 | 输出要求 |
|---|---|---:|---|
| 意图 | 20% | 开头写明：回应什么任务 / 支撑谁做什么决定 / 本轮边界（**做什么、不做什么**） |
| 策略 | 35% | 明确选了什么（禁止只罗列选项等接收者选）；每个关键选择带依据；什么条件下改选 |
| 执行 | 35% | 谁做什么产出什么 / 时间·依赖·等待期安排 / 完成判据（怎样算做完） |
| 表达 | 10% | 数字口径一致；结论—依据—行动对应；接收者不需重新整理即可用 |

篇幅精力按权重分配（策略+执行是主战场，文笔只占 10%）。

### 表达铁律
- 结论与假设分开写；未核实写"未核实/待确认"；未表态写"未表态"；未说明写"未说明"。**不许把"预计降本，尚无测试数据"写成"可以降本"**
- 边界用成句声明：而非 / 暂不 / 仅限 / 只做 / 不包括
- 禁套话、禁重复、禁模板句（引号内引用原文豁免）；每段承接推进上一段
- 依据只能来自输入材料或可查来源；没有就写没有，**不许编**

### 四条件省略闸
凡打算省略或略写某项，四问全过才可省，否则不删、显式降级标注：
1. **当前阶段必须吗？**（以后才需要的 → 标注"后续"）
2. **属于提交者该做的判断，或须为其备齐决定所需信息？**（审批方的事 → 写"待 XX 决定"，但决定所需信息仍要备齐）
3. **全文确实没做吗？**（分散在别处已完成 → 不省，指过去）
4. **影响当前决定或行动吗？**（只增加阅读成本 → 降为"建议"）

## 阶段三：交付前自检（生成后）

**评审方式**（在体检摘要里如实标注用的是哪种）：
- 优先：环境支持时用**独立评审**（如 Hermes 的 delegate 子代理/另一个会话）。**指令必须自包含**：任务原话 + 义务表 + 全文 + 本 skill 的评分锚点一并传给评审方，不得假设它知道上下文
- 退而求其次：同上下文内显式标注"以下为评审视角"重读【任务原话 + 全文】自评——**明确这是自评，偏松，且自评时引文核对价值有限（自己编的自己核对不出来）**

**评审基准三档**（决定结论能说多重的话）：
- `task`：有任务原话 → 可判"任务承接"
- `self-stated`：审查别人文件且无原话 → 只能按文档自述目标判，结论第一行必须写"**按自述目标：已满足（未对真实任务判定）**"——括号不可省，读者只读第一行
- `none`：两者都无 → 只列检查清单，不下承接结论

自检前先确认：任务原话与全文是否仍在上下文中；已被压缩掉的关键原文，允许**重读文件一次**（这是"不重复读文件"纪律的唯一例外）。执行：

1. **按十二格评分** 0–10（0.5 一档，锚点之间取语义最接近者）。全锚点：

| 分 | 含义 | 判法 |
|---|---|---|
| 10 | 本阶段必要工作已完成（≠无懈可击） | 接收者可直接履行正常决策/审批/协作 |
| 9 | 仅措辞瑕疵 | 只剩排版/措辞/编号问题，不改变任何判断 |
| 8 | 一处小不精确 | 接收者不用问、自己就能定下来 |
| 7 | 局部补充 | 一至两处局部缺口，接收者问一句就能继续 |
| 6 | 影响次要动作 | 缺口已影响一个次要动作，不补会返工，但主决策仍可推进 |
| 5 | 关键判断做了一半 | 方向有了数没有／结论有了依据没有／动作有了验收没有 |
| 4 | 关键信息缺一块 | 接收者必须回来问一次才能推进主决策 |
| 3 | 关键工作大部未做 | 主要成果成型，但核心判断仍要接收者自己完成 |
| 2 | 只给了材料与方向 | 接收者要自己做核心工作 |
| 1 | 零散素材 | 未形成可用成果，接收者要从零组织 |
| 0 | 未形成有效成果或明显偏离任务 | 需要重新开展 |

   **层分 = 本层最弱格 ÷10×100（不取平均）**；层分旁**并列披露平均分**（让读者看见"平均洗掉了多少"）；≤5 为关键缺口，≤2.5 为核心方向重做。
   **未评格规则**：层内已评格 ≥2 → 层分按已评格最弱计，标注"仅按已评格"；已评格 <2 → 该层标"未判定"，不进任何结论，写明原因（不许把没评的层当满分或当 0 分）
   **分数声明**：分数是语义插值，跨评审者不可比，误差约 ±1 档——摘要里照实写，不许报精确小数假装精确
   **缺口归格**：长任务分组义务的缺口按性质归格——执行类缺谁/何时/判据 → E1/E2/E3；选择与依据类 → S1/S2/S3；跑题与边界类 → I 层
2. **逐字核对证据**：每个关键判断的引文/数字回原文逐字比对（含标点空格）；对不上的，该判断降级为"不可采信"。禁止凭记忆写引文——复制，不要回忆
3. **状态自洽**："已满足/已完成"必须能指到证据；"冲突"必须指到互相矛盾的两处；"缺"必须说明缺在哪
4. **省略项复查**四条件闸
5. **出体检摘要**（固定模板）再交付：

```markdown
## 交付体检摘要（内部用）
意图 X（均Y）｜策略 X（均Y）｜执行 X（均Y）｜表达 X（均Y）（层分=本层最弱格÷10×100；未评格≥2 的层标"未判定"；分数跨评审者不可比，误差约±1档）
基准：task / self-stated / none　评审方式：独立评审 / 同上下文自评
结论：重新形成方案 / 补充相关部分 / 先推进不受影响的工作 / 可以推进（可并存）
缺口：
- [格ID] 缺口描述 → 补什么 + 补到什么程度过关（resolutionTest）
- 未能当场补的 → 剩余工作清单
待确认项：……（未知不进结论，单列）
（自检为软校验；关键数字、合规条款建议人工复核）
```

6. 缺口能当场补的当场补；不能补的显式列**剩余工作清单**随交付给出。**修补只做一轮**：补完后在摘要标注"修补后未复评"；若摘要分数不变，注明"分数对应修补前版本"
7. **摘要分级**：交付给内部同事 = 正文 + 体检摘要；交付给外部（客户/供应商）或发到公开平台 = 只交正文，体检摘要留内部存档。**交付目标不明时按外部处理**（保守默认：不附摘要）

### 成本纪律（token）
- 自检一次读完、一次评完，复用上下文里的全文，**不重复读取同一文件**
- 轻任务（短文案/邮件）自检压缩为一条目视检查，不跑全套评分

## 绝对不做

- 不输出"AI 生成概率"——文风不是作者身份的证据
- 不因"字段齐全"给高分——判的是判断有没有做，不是格子有没有填
- 不用自检分数做绩效判断；分数只作横向粗筛与讨论起点
- 收单期用户跳过确认时不擅自定边界（标注"assumed"）
- 判不了就写"未判定"——**"我没看"不许印成"没问题"**
- 修改评分锚点或闸门规则必须升版本号——**自评分数跨版本不可比**，并列展示必须带版本标注

## 常见陷阱

| 陷阱 | 对策 |
|---|---|
| 看着已有材料拆义务（拆出的一定是材料里有的） | 先看任务原话，拆完再看材料 |
| 把最佳实践当任务要求 | 用户没要的不算缺陷 |
| 一条缺陷拆多条重复扣分 | 同一根因合并成一条 |
| 凭记忆写引文 | 逐字复制原文 |
| 把"待确认"当"已确认"或当"缺失" | 未知不进任何结论，单列"待确认" |
| 义务表形似神不似（只有 question 没有可判标准） | resolutionTest 必须"补到一眼能判"，形容词直接退回重拆 |

## 诚实声明（附在每份体检摘要后）

自检是软校验；关键数字、合规条款、对外文档建议人工复核。
